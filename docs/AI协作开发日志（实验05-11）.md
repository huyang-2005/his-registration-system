# AI 协作开发日志（实验五 ~ 实验十一）

> 用途：学习通各实验“AI 协作记录”栏可直接摘录对应段落；答辩“AI 怎么修 bug”用实验七段落。

## 实验五 · 排班号源与挂号事务

- 提示词：为 @backend 添加排班号源查询与挂号 API；挂号必须在事务内扣号源并生成排队号；号源不足返回 409；先给方案。
- AI 产出：初版“先查 used_quota 再 update”，未使用事务，高并发会超号。
- 人工修改：改为 `db.transaction()`（`BEGIN IMMEDIATE`），在事务内校验并自增；新增 409 分支。
- 验证：连续挂号两次，剩余号源 5→3，排队号 1/2；满号用例返回 409。
- 最难 bug：pytest 夹具与种子排班同日导致唯一约束冲突；给 AI 的反馈含完整报错 + @conftest.py + 期望“每个用例独立数据”；最终把 fixture 日期改为 +5 天。

## 实验六 · 业务闭环

- 提示词：新增药品档案与库存；医生开方自动划价；收费事务=写收费单+标记已收费+扣库存；库存不足 400；金额不得信任前端。
- AI 产出：初版让前端传 `price` 并参与计算；收费分三步提交。
- 人工修改：单价只查 `drug` 表；`Decimal` 划价；三步写入同一事务；库存按效期 FIFO。
- 迁移练习：给药品表加医保类别，生成 `m002_insurance_category.py`，先检查列存在性再 ALTER，不删表。
- 验证：开方 3 盒×10 元=30 元；收费后库存 100→97；库存 2 时收费 3 返回 400 且库存不变。

## 实验七 · 认证权限与安全

- 提示词：加 bcrypt 登录、JWT、RBAC 四角色；管理接口仅 admin；提供 /me；先给方案。
- AI 产出：方案完整，但迁移重建 `sys_user` 时直接 DROP TABLE，外键引用会失败。
- 人工修改：先提交 → `PRAGMA foreign_keys=OFF` → 建新表保留 `user_id` → 回填 bcrypt → `PRAGMA foreign_keys=ON`；迁移前自动备份。
- 验证：无 token 401；收费员访问 `/api/audit` 403；管理员 200；库中密码为 `$2b$` 哈希。

## 实验八 · 测试与代码质量

- 提示词：为 @app/services 的划价/库存/挂号写 pytest，覆盖正常、0、不存在、库存为 1；先列用例清单。
- AI 产出：用例覆盖较好，但 TestClient 断言 303 未考虑默认跟随重定向；参数化查询漏写逗号导致 `sqlite3.ProgrammingError`。
- 人工修改：显式 `follow_redirects=False`；修正元组参数；补“退号与处方冲突”用例。
- Code Review：发现 5 个真实问题并修复（详见 `实验08-测试与CodeReview报告.md`）。
- 结果：41 passed；核心 service 覆盖率 76%~93%。

## 实验九 · 部署与运维

- 提示词：生成 Dockerfile、docker-compose.yml（SQLite 数据卷）、.env.example、GitHub Actions（pytest + docker build）。
- AI 产出：可用；初版镜像以 root 运行、未配 HEALTHCHECK。
- 人工修改：非 root 用户、`/data` 数据卷、健康检查、CI 中注入测试环境变量。
- 验证：本地 uvicorn 启动与页面冒烟通过；Docker 配置已提交，待有 Docker 环境执行 `docker compose up --build`。

## 实验十 · 数据字典与审计

- 提示词：药品 CSV 导入（编码识别/逐行校验/去重/错误报告）；审计中间件自动记录写操作；今日统计报表。
- AI 产出：初版只按 UTF-8 读取，Excel 的 GBK 文件直接失败；审计在业务代码里零散写。
- 人工修改：编码链 `utf-8-sig → utf-8 → gbk → gb18030`；审计改为中间件 + `WRITE_RULES`；报表补齐处方收入。
- 验证：导入 100 合法 + 5 错误 → 成功 100、失败 5，错误行不影响合法行；审计可查发药记录。

## 实验十一 · AI 增强与伦理

- 提示词：实现智能分诊，提示词独立文件、10 秒超时、固定 JSON、失败兜底全科门诊、页面免责声明。
- AI 产出：调用与解析基本正确；初版未处理 ```json 包裹与 `advice` 为字符串的情况。
- 人工修改：去除 Markdown 包裹；统一 `advice` 为数组且最多 5 条；`urgency` 枚举校验；未配置 Key 直接兜底。
- 验证：空输入/短文本兜底；改错 Key 兜底；配置真实 Key 后输入“肚子疼、发烧两天”返回结构化建议且 `source=ai`（科室由模型判断，实测出现过“全科门诊”与“急诊科”，均属正常）。

## 贯穿全程的人工决策

1. 业务红线由人定：金额后端算、事务原子性、退号与处方联动、权限最小化。
2. AI 产出必须可验证：每步“生成 → 运行/测试 → 提交”，不一次性接受大段代码。
3. 报错三件套：完整报错原文 + @ 相关文件 + 期望行为，显著提高修复命中率。
