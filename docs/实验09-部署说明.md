# 实验九 · 部署与运维说明

## 一、部署架构

本项目为服务端渲染单体应用，前后端同进程：

```
浏览器 ──HTTPS──> FastAPI(uvicorn) ──> SQLite(his.db)
                         │
                         ├─ Jinja2 模板
                         └─ DeepSeek API（仅智能分诊，可选）
```

- 前端不需要单独部署（无独立构建产物）。
- 数据库为单文件 SQLite，Docker 部署时挂载数据卷。
- AI 分诊为可选外部依赖，未配置 Key 时自动兜底。

## 二、环境变量

| 变量 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `SECRET_KEY` | 生产必填 | 开发自动生成到 `data/.secret_key` | 会话与 JWT 签名密钥，≥32 位随机串 |
| `HIS_DB_PATH` | 否 | `./his.db` | SQLite 文件路径；Docker 内为 `/data/his.db` |
| `HIS_DATA_DIR` | 否 | `./data` | 备份、密钥文件目录 |
| `HIS_DEMO_PASSWORD` | 否 | `His@123456` | 初始化/迁移时演示账号密码 |
| `DEEPSEEK_API_KEY` | 否 | 空 | 不填则智能分诊走兜底 |
| `DEEPSEEK_BASE_URL` | 否 | `https://api.deepseek.com` | API 地址 |
| `DEEPSEEK_MODEL` | 否 | `deepseek-chat` | 模型名 |
| `TRIAGE_TIMEOUT_SECONDS` | 否 | `10` | AI 超时秒数 |
| `COOKIE_SECURE` | 否 | `0` | HTTPS 部署时设为 `1` |

配置文件模板：`.env.example`（只有变量名/占位值，无真实密钥）。

## 三、本地运行

```bash
python -m pip install -r requirements.txt
python scripts/refresh_demo_data.py
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

首次启动会自动建库并执行迁移；后续启动只执行未应用的迁移。

## 四、Docker 一键启动

```bash
copy .env.example .env
# 编辑 .env：至少填写 SECRET_KEY
docker compose up --build
```

访问 `http://127.0.0.1:8000`。数据卷 `his_data` 挂载到 `/data`，容器重建不丢数据。

```bash
# 停止
docker compose down
# 停止并删除数据卷（谨慎）
docker compose down -v
```

验证点：
1. `docker compose ps` 显示服务 healthy。
2. 浏览器可打开登录页并完成一次挂号。
3. `docker compose logs -f his` 无异常堆栈。

## 五、免费云部署（Render，手把手）

> 目标：让老师用公网 URL 打开系统。全程不需要买服务器，按下面 8 步做。

### 第 1 步：把代码放到 GitHub

> **第 7 组已有仓库**：`https://github.com/huyang-2005/his-registration-system`。不用新建仓库，直接看下面“已有仓库怎么更新”。

**新建仓库（其他组）**：
1. 注册/登录 GitHub，点右上角 `+` → `New repository`。
2. 仓库名填 `his-outpatient`，选 `Private` 或 `Public`（Private 也能部署，Render 会授权）。
3. 不要勾选 “Add a README”，创建后按 GitHub 页面提示上传代码。
4. 最省事的方式：在本机项目目录执行（把 URL 换成你的仓库地址）：

```bash
git init
git add .
git commit -m "feat: HIS 门诊挂号与收费发药分系统"
git branch -M main
git remote add origin https://github.com/你的用户名/his-outpatient.git
git push -u origin main
```

**已有仓库怎么更新（第 7 组）**：

本机 `origin` 已指向 `huyang-2005/his-registration-system`，当前在 `feat/full-delivery` 分支，`main` 与 `origin/main` 同步。每次实验完成或部署前执行：

```bash
# 1. 先看改了什么，确认 .env 不在列表里
git status

# 2. 暂存并提交（.env 已被忽略；his.db 是虚构演示数据，可一并提交）
git add .
git commit -m "feat: 完成挂号收费发药闭环、RBAC、审计、AI 分诊与验收材料"

# 3. 推功能分支
git push origin feat/full-delivery

# 4. 合并到 main（Render 默认部署 main）
git checkout main
git pull origin main
git merge feat/full-delivery
git push origin main

# 5. 回到开发分支继续改
git checkout feat/full-delivery
```

> 如果 `git push` 提示没有权限，先在 GitHub 确认你是仓库协作者，或用 `gh auth login` / Personal Access Token 登录。
> 如果 `git push` 报 `Connection was reset` / `Couldn't connect to server`，说明当时网络到 GitHub 的 443 不通：改用 SSH 推送（本机已配置密钥 `~/.ssh/id_ed25519_his`，`origin` 已切为 `git@github.com:huyang-2005/his-registration-system.git`），并在每次 push 前设置 `GIT_SSH_COMMAND="ssh -i ~/.ssh/id_ed25519_his -o IdentitiesOnly=yes"`。
> 如果只想先更新代码、不合并，执行到第 3 步即可；但 Render 要部署 `main` 分支，所以最终要执行第 4 步。

> 注意：`.env` 已被 `.gitignore` 忽略，不会被推上去；真实 API Key 不会泄露。

### 第 2 步：注册 Render

1. 打开 https://render.com ，用 GitHub 账号登录（最方便）。
2. 首次登录按提示授权 Render 读取你的仓库。

### 第 3 步：新建 Web Service

1. 控制台点 `New` → `Web Service`（如果仓库根目录有 `render.yaml`，也可以点 `New` → `Blueprint`）。
2. 选择 `Build and deploy from a Git repository` → 连接 GitHub → 选 `huyang-2005/his-registration-system`。
3. Branch 选 `main`；如果仓库根目录有 `render.yaml`，Render 会自动识别；没有就按第 4 步手动填。

### 第 4 步：填写构建与启动命令

| 项 | 填写 |
| --- | --- |
| Runtime | Python 3 |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `python scripts/refresh_demo_data.py && uvicorn app.main:app --host 0.0.0.0 --port $PORT` |
| Plan | Free |

> 启动命令先预热演示数据再启动服务；每次重启/冷启动都会自动补齐当天排班、药品、挂号、处方。

### 第 5 步：配置环境变量

在 `Environment` 页逐条添加：

| Key | Value | 说明 |
| --- | --- | --- |
| `SECRET_KEY` | 点 `Generate` 自动生成 | 不要手写固定值 |
| `HIS_DB_PATH` | `/tmp/his.db` | 免费层临时磁盘 |
| `HIS_DATA_DIR` | `/tmp/data` | 备份/密钥目录 |
| `HIS_DEMO_PASSWORD` | `His@123456` | 演示账号密码 |
| `DEEPSEEK_API_KEY` | 你的 Key | 只填在 Render 后台，不写进仓库 |
| `COOKIE_SECURE` | `1` | HTTPS 下更安全 |

### 第 6 步：部署并拿到公网 URL

1. 点 `Create Web Service`，等待日志出现 `Uvicorn running on ...`。
2. 页面顶部会显示形如 `https://his-outpatient.onrender.com` 的 URL。
3. 打开该 URL + `/login`，用 `admin / His@123456` 登录。
4. 把这个 URL 填进 PPT 第 12 页、核验表和提交清单。

### 第 7 步：验收（手机流量也试一次）

- [ ] 公网 HTTPS 能打开登录页
- [ ] 能完成一次挂号 → 开方 → 收费 → 发药
- [ ] `/audit` 能查到刚做的操作
- [ ] `/triage` 返回 AI 结果（或说明已走兜底）

### 第 8 步：免费层注意事项

1. Render 免费实例 15 分钟无访问会休眠，首次唤醒要等 30~60 秒。**答辩前 10 分钟先打开一次预热。**
2. 免费层磁盘是临时的，重启/重新部署后 SQLite 会重置；启动命令会自动重新预热演示数据，所以演示仍可用，但历史操作记录不跨重启保留。
3. 如果老师要求“数据重启不丢”，需要升级 Render 持久磁盘，或改用本地 Docker + 内网访问，二者选一即可。
4. 部署失败先看 `Logs`：常见原因是 `SECRET_KEY` 没配、`requirements.txt` 路径不对、启动命令端口没写 `$PORT`。

### 不想用 Render 的替代方案

- **本地 Docker**：`docker compose up --build`，用 `http://本机IP:8000` 让同网段老师访问。
- **Railway / Fly.io**：同样支持 Dockerfile，步骤与 Render 类似，挂载卷后 SQLite 可持久化。

> 当前仓库已包含 `render.yaml`，Render 可直接按蓝图读取构建/启动命令与环境变量；`DEEPSEEK_API_KEY` 设为 `sync: false`，必须在后台手动填一次。
