## 三、2 分钟答辩三问（必背）

### 问题 1：最难 bug 是什么？怎么让 AI 修的？

**推荐回答（真实且可验证）**：

> 最难的是实验七做 RBAC 时重建 `sys_user` 表。迁移脚本要保留原有 `user_id`，但 `registration.operator_id` 有外键引用，直接重建会触发外键约束失败。
>
> 给 AI 的反馈用了“报错三件套”：完整报错原文 + @ 引用 `app/migrations/m003_auth_rbac.py` 和 `app/db.py` + 期望行为“迁移可重复执行、历史挂号单不丢失”。
>
> AI 第一版建议直接 `DROP TABLE`，被我们否掉——这违反“禁止删库重建”。人工改成：先提交当前事务 → `PRAGMA foreign_keys=OFF` → 建新表并保留 `user_id` → 回填 bcrypt 密码 → 重建索引 → `PRAGMA foreign_keys=ON` → 再提交。最后在数据库副本上跑了迁移和全量测试，确认 `registration` 引用完好。
>
> 收获：AI 能给方案，但“数据不能丢”这条业务红线必须人来守。

### 问题 2：哪些代码是人工改的、为什么？

按“AI 不会主动想到的业务规则”回答，至少说 3 点：

1. **金额计算**：AI 初版用 `float` 并接受前端传价格。人工改为 `Decimal` + `ROUND_HALF_UP`，单价只从 `drug` 表读取，前端不传价格。
2. **并发安全**：AI 初版是“先查再改”，高并发会超号。人工改为 `BEGIN IMMEDIATE` 事务，在事务内校验 `used_quota < total_quota` 后再自增。
3. **收费原子性**：人工要求“写收费单 + 置已收费 + 扣库存”必须在同一事务，库存不足 400 且整体回滚；并补了对应测试。
4. **CSV 编码**：AI 初版只按 UTF-8 读，Excel 导出的 GBK 直接报错。人工增加 `utf-8-sig → utf-8 → gbk → gb18030` 依次尝试。
5. **审计日志**：AI 初版在业务代码里零散写日志。人工改为中间件 + `WRITE_RULES` 分类表，保证新增写接口不漏记。
6. **403 页面**：异常处理器里直接渲染模板时状态码被重置为 200，人工改为渲染后显式 `response.status_code = 403`。

### 问题 3：重做一遍，哪里会不一样？

> 三件事：
> 1. 先定数据模型和迁移机制，再写功能。我们前期是单文件 `app.py`，后期才拆 `routers/services/schemas`，返工成本高。
> 2. 测试前置。挂号事务、库存扣减、权限这些关键路径应该先写测试再让 AI 实现，而不是做完再补。
> 3. 金额与状态机一开始就用强类型/枚举，避免 `float`、字符串状态散落各处。
>
> 另外会把 E2E 提前到实验六，而不是最后补。

## 四、教师可能追问（准备一句答案）

| 追问 | 回答要点 |
| --- | --- |
| SQL 注入怎么防？ | 所有 SQL 用参数化 `?` 占位，不拼接用户输入；`LIKE` 也只拼参数值。 |
| XSS 怎么防？ | Jinja2 默认自动转义；不使用 `|safe` 渲染用户输入。 |
| CSRF 怎么防？ | Cookie 设置 `SameSite=Lax` + 写操作只接受 POST；当前未加 CSRF Token，是已知改进点。 |
| 密码为什么用 bcrypt？ | 加盐、可调成本、抗暴力破解；MD5/SHA1 无盐且易碰撞，不适合存密码。 |
| JWT 放哪里？ | HttpOnly Cookie 防 JS 读取；同时支持 `Authorization: Bearer` 便于 API 调试。 |
| 为什么用 SQLite？ | 教学项目零运维、单文件易演示；生产应换 PostgreSQL，代码已通过 `db.py` 收敛连接。 |
| 迁移怎么保证不丢数据？ | 迁移前自动备份到 `data/backup/`；只新增迁移文件；重建表保留主键；迁移可重复执行。 |
| 审计日志会不会被改？ | 当前只做应用层留痕；生产应追加只写库/日志服务器并做哈希链。 |
| AI 幻觉怎么办？ | 固定 JSON 结构 + 枚举校验 + 10 秒超时 + 失败兜底 + 页面免责声明；AI 只辅助不决策。 |
| 并发挂号怎么测？ | `BEGIN IMMEDIATE` 串行化写事务；单测覆盖满号 409，另可用多线程脚本压测。 |
| 退号后库存/费用怎么办？ | 退号释放号源；已收费的挂号 payment 置“已退费”；处方退费未实现，是后续方向。 |
| 有没有真实患者数据？ | 没有，全部为虚构姓名/证件号；演示数据由脚本生成。 |
| 明文密码修了吗？ | 已修：种子密码为空，迁移 003 统一 bcrypt 写入；库中只有 `$2b$` 哈希。 |

## 五、不会答时怎么办

1. 先确认问题：“您问的是并发下的号源扣减，还是退号释放号源？”
2. 会多少说多少，明确边界：“这部分目前实现了 X，Y 还没做，原因是 Z。”
3. 不要编。可以答：“这个点我们没有实测，回去会用……验证。”
4. 把问题转回已验证的事实：“但我们的测试覆盖了……，结果是……。”
