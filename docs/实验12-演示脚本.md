# 实验十二 · 5 分钟演示脚本

> 目标：5 分钟内走完 A 路线闭环，并覆盖“越权 403 / pytest 全绿 / 审计可查”三件套。
> 总时长控制在 4:50 左右，留 10 秒缓冲。

## 0. 课前准备（务必按顺序）

```bash
# 1) 预热今天的数据（可重复执行）
python scripts/refresh_demo_data.py
# 2) 启动服务（答辩时不要用 --reload）
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
# 3) 另开一个终端，提前跑一次测试，留好截图
python -m pytest tests -q --ignore=tests/e2e
python scripts/verify_rbac.py
```

浏览器提前打开 `http://127.0.0.1:8000/login`，确认未登录。
演示账号统一密码：`His@123456`。

**备用方案**：若页面异常，用 API 走同一条链路（见文末），并口头说明“页面与 API 共用同一 service 层”。

## 1. 时间轴

| 时间 | 角色 | 页面 | 操作 | 讲解词（要点） |
| --- | --- | --- | --- | --- |
| 0:00–0:20 | admin | `/login` → `/` | 登录，展示首页统计卡片 | “四角色 RBAC；JWT 放 HttpOnly Cookie；首页是今日挂号、收入、待收费、待发药” |
| 0:20–0:40 | admin | `/base-data` | 展示科室/医生列表（不新增） | “基础数据可维护，科室/医生启停用” |
| 0:40–1:30 | cashier | `/register` | 选患者“刘建国”，选“内科/张伟/上午/普通”，确认挂号 | “号源在事务内扣减，生成挂号单和排队号；满号会返回 409” |
| 1:30–2:20 | doctor | `/prescriptions/new` | 选刘建国今日挂号单，诊断“上呼吸道感染”，加“阿莫西林胶囊×2、布洛芬缓释胶囊×1”，提交 | “金额由后端按药品单价计算：12.50×2 + 18.00 = 43.00，前端没有价格输入框” |
| 2:20–3:00 | cashier | `/cashier` | 找到该处方，展示明细，点“收费” | “收费=写收费单+处方置已收费+FIFO 扣库存，三步同一事务；库存不足会整体回滚并提示” |
| 3:00–3:30 | pharmacist | `/pharmacy` | 在“已收费”列表点“发药” | “只有已收费才能发药；重复发药 409；发药记录写入 dispense_record” |
| 3:30–4:20 | admin | `/audit` | 按动作筛选：挂号、开方、处方收费、发药 | “写操作由中间件自动留痕：谁、何时、对象、IP、详情；不是业务代码里手写的” |
| 4:20–4:45 | admin | `/report` | 打开今日报表 | “挂号量、退号率、挂号收入、处方收入，按科室/医生汇总，与刚才操作一致” |
| 4:45–5:00 | admin | `/triage` | 输入“肚子疼、发烧两天，还有点恶心”，提交 | “AI 仅辅助：固定 JSON、10 秒超时、失败兜底全科门诊；正常调用返回结构完整的建议（`source=ai`），具体科室以模型判断为准，页面有免责声明” |

## 2. 每一步的预期结果（验收对照）

1. 登录成功进入首页，导航按角色裁剪（收费员看不到审计日志）。
2. 挂号成功提示“挂号成功，挂号单号 GH…，排队序号 N”；该号源剩余数 -1。
3. 开方成功提示“开方成功：CF…，合计 43.00 元”。
4. 收费台该处方消失并出现在“今日收费记录”，金额 43.00。
5. 药房“已收费”列表该处方消失，出现在“今日发药记录”。
6. 审计日志能查到 4 条：挂号、开方、处方收费、发药，操作人分别为 cashier/doctor/cashier/pharmacist。
7. 报表今日挂号量 +1，处方收入 +43.00。
8. 智能分诊返回科室/紧急程度/注意事项/免责声明（本机已配置 Key，实测 `source=ai`、结构完整；返回科室由模型判断，可能是“全科门诊”或“急诊科”，不必强求固定值）；断网或未配 Key 时返回“全科门诊”兜底。

## 3. 现场抽查应对

| 教师抽查 | 你的操作 | 预期 |
| --- | --- | --- |
| 越权访问 | 终端执行 `python scripts/verify_rbac.py`，或收费员登录后访问 `/audit` | 403 / 脚本输出“全部通过” |

| 并发/超号 | 口头说明：`BEGIN IMMEDIATE` + 事务内 `used_quota` 校验 | 不会超号 |

## 4. API 备用链路（页面故障时）

```bash
# 登录（收费员）
curl -X POST http://127.0.0.1:8000/api/auth/login -H "Content-Type: application/json" -d "{\"username\":\"cashier\",\"password\":\"His@123456\"}"

# 挂号（把 schedule_id 换成当天有号源的排班）
curl -X POST http://127.0.0.1:8000/api/register -H "Authorization: Bearer <token>" -H "Content-Type: application/json" -d "{\"schedule_id\":1,\"patient_name\":\"演示患者\",\"patient_id_card\":\"110101199001019999\",\"phone\":\"13800009999\"}"

# 开方（医生 token）
curl -X POST http://127.0.0.1:8000/api/prescriptions -H "Authorization: Bearer <doctor_token>" -H "Content-Type: application/json" -d "{\"reg_id\":<reg_id>,\"diagnosis\":\"上呼吸道感染\",\"items\":[{\"drug_id\":1,\"quantity\":2}]}"

# 收费（收费员 token）
curl -X POST http://127.0.0.1:8000/api/prescriptions/<presc_id>/pay -H "Authorization: Bearer <cashier_token>" -H "Content-Type: application/json" -d "{\"pay_type\":\"现金\"}"

# 发药（药师 token）
curl -X POST http://127.0.0.1:8000/api/prescriptions/<presc_id>/dispense -H "Authorization: Bearer <pharmacist_token>"
```
