# 实验十二 · 课程复盘与个人总结模板

## 一、小组复盘（1 分钟发言稿）

**最大收获**：从“让 AI 写代码”变成“给 AI 定边界、用测试验收”。每步只做一件可验证的事，AI 产出必须跑通测试才接受。

**最大教训**：业务规则 AI 不会主动替你想。金额后端计算、挂号/收费事务、退号与处方状态联动、权限最小化，都是人工补上的；如果不写测试，这些问题在演示时才会暴露。

**踩过的坑（对照“vibe coding 十大坑”）**：

| 坑 | 本组表现 | 应对 |
| --- | --- | --- |
| 一次让 AI 做太多 | 初期想让 AI 一次生成整个挂号+收费 | 拆成“排班→挂号→前端”三步，每步验证 |
| 不看代码就接受 | 迁移脚本直接 DROP TABLE | 人工复核外键与数据保留 |
| 不写测试 | 改一处坏一处 | 补 pytest，关键路径回归 |
| 报错描述不清 | 只说“跑不起来” | 用报错三件套：原文+@文件+期望 |
| 忽视并发 | 先查再改导致超号 | `BEGIN IMMEDIATE` 事务内校验 |
| 信任前端 | 前端传价格 | 后端按药品档案重算 |
| 密钥进仓库 | 早期硬编码 SECRET_KEY | 环境变量 + `.gitignore` |
| 目录随意 | 单文件 app.py | 重构为 routers/services/schemas |
| 假数据当真 | 演示库为空/日期过期 | `refresh_demo_data.py` 幂等预热 |
| 演示前不预演 | 账号/端口临时出问题 | 演示脚本 + 备用 API 链路 |
