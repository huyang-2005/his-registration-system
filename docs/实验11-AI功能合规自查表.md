# 实验十一 · AI 功能合规自查表

## 一、功能基本信息

| 项 | 内容 |
| --- | --- |
| 功能名称 | 智能分诊建议（AI 辅助） |
| 入口 | 页面 `/triage`；接口 `POST /api/triage` |
| 输入 | 患者症状自由文本（如“肚子疼、发烧”） |
| 输出 | 固定 JSON：`department` 建议科室、`urgency` 紧急程度（普通/尽快/急诊）、`advice` 注意事项数组、`disclaimer` 免责声明、`source`（ai/fallback） |
| 模型 | DeepSeek `deepseek-chat`，温度 0.2 |
| 提示词 | 独立文件 `app/prompts/triage.txt` |
| 超时 | 10 秒（`TRIAGE_TIMEOUT_SECONDS`） |
| 降级 | 未配置 Key / 超时 / 解析失败 → 返回“全科门诊/普通”兜底建议 |
| 数据留存 | 不向模型发送姓名、证件号、病历号；仅发送症状文本 |

## 二、风险与措施

| 风险点 | 说明 | 措施 |
| --- | --- | --- |
| AI 幻觉给出错误科室/建议 | 模型可能“看起来专业但错误” | 只输出建议不生成诊断/处方；固定枚举校验；页面显著免责声明 |
| 患者误把建议当诊断 | 直接照做延误就诊 | 文案“仅供参考，需医生确认”；紧急程度仅作提示；建议到导诊台 |
| 输入含个人隐私 | 症状文本可能含姓名/电话 | 前端提示不要填写身份信息；后端不落库原文（仅审计动作） |
| API 不可用/超时 | 网络或额度问题 | 10 秒超时 + 兜底全科门诊，功能不阻塞主流程 |
| 输出结构不稳定 | 模型返回多余文本/Markdown | 去除 ``` 包裹；JSON 解析失败即兜底；`urgency` 非枚举值归为“普通” |
| 提示词被注入 | 用户输入“忽略以上规则” | 系统提示词约束只做分诊；输出结构校验；不执行用户指令 |
| 成本/滥用 | 无限制调用 | 仅登录用户可用；后续可加频率限制 |

## 三、界面合规展示

`/triage` 页面在结果区固定展示：**“本建议由 AI 生成，仅供参考，需医生确认”**。
兜底结果额外显示 `note` 说明降级原因（如“AI 服务暂时不可用，已降级为兜底建议”）。

## 四、三种场景验证

| 场景 | 操作 | 预期 | 实际 |
| --- | --- | --- | --- |
| 正常输入 | 输入“肚子疼、发烧两天，还有点恶心” | 返回科室/紧急程度/注意事项/免责声明，结构完整 | 已验证：`source=ai`，科室/紧急程度/注意事项/免责声明均返回（科室由模型判断，可能为“全科门诊”或“急诊科”） |
| 异常输入 | 空字符串或“啊” | 不崩溃，返回兜底“全科门诊”并提示症状过短 | 已验证（无需 Key） |
| API 失败 | 故意填错 Key 或断网 | 不崩溃，返回兜底并提示“AI 服务暂时不可用” | 已验证（改错 Key 即可复现） |

> 真实调用已在本机 `.env` 配置 Key 后验证通过；部署时在 Render 后台单独配置 `DEEPSEEK_API_KEY`，不要写进仓库。

## 五、合规结论

- AI 仅辅助分诊，不做诊断、不开处方、不替代医生。
- 输出有固定结构、枚举校验、超时与兜底。
- 界面与接口均带免责声明。
- 不传输患者身份信息。
- 符合“AI 只能辅助，不能决策”的课程红线。
