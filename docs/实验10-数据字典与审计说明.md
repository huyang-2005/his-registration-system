# 实验十 · 数据字典与审计说明

## 一、核心数据表

| 表 | 用途 | 关键字段 | 标准化说明 |
| --- | --- | --- | --- |
| `department` | 科室字典 | `dept_code`、`dept_name`、`dept_type`、`status` | 编码唯一；类型限定门诊/急诊；支持启停用 |
| `doctor` | 医生字典 | `doctor_code`、`doctor_name`、`dept_id`、`title`、`status` | 编码唯一；关联科室；在岗/离岗 |
| `registration_level` | 号别字典 | `level_code`、`level_name`、`reg_fee`、`diagnosis_fee` | 费用由号别决定，挂号时快照到挂号单 |
| `doctor_schedule` | 排班号源 | `doctor_id`、`work_date`、`time_period`、`total_quota`、`used_quota`、`status` | 医生+日期+时段唯一；剩余=总数-已用 |
| `patient` | 患者主索引 | `medical_record_no`、`id_card`、`patient_type`、`insurance_no` | 病历号唯一；证件号唯一（非空时）；医保患者必须有医保号 |
| `registration` | 挂号单 | `reg_no`、`queue_no`、`status`、`fee`、`operator_id` | 状态：已挂号/已就诊/已退号；单号按日生成 |
| `payment` | 挂号收费 | `reg_id`、`amount`、`pay_type`、`status`、`operator_id` | 一挂号单最多一条有效收费；退号置已退费 |
| `drug` | 药品字典 | `drug_code`、`generic_name`、`spec`、`dosage_form`、`price`、`insurance_category` | 通用名+规格去重；医保类别甲/乙/丙/自费 |
| `drug_inventory` | 药品库存 | `drug_id`、`batch_no`、`quantity`、`expiry_date` | 按批次；收费时按效期 FIFO 扣减 |
| `prescription` | 处方 | `presc_no`、`reg_id`、`diagnosis`、`status`、`total_amount` | 状态：待收费/已收费/已发药 |
| `prescription_item` | 处方明细 | `drug_id`、`drug_name`、`spec`、`quantity`、`unit_price`、`amount` | 单价与金额均为开方时快照 |
| `presc_payment` | 处方收费 | `presc_id`、`amount`、`pay_type`、`status` | 一处方最多一条有效收费 |
| `dispense_record` | 发药记录 | `presc_id`、`operator_id`、`dispensed_at` | 仅已收费处方可发药 |
| `sys_user` | 用户 | `username`、`password_hash`、`role`、`status` | 四角色；密码 bcrypt |
| `audit_log` | 审计日志 | `user_id`、`username`、`action`、`object_type`、`object_id`、`detail`、`ip`、`created_at` | 写操作自动留痕 |

## 二、标准字典落地情况

| 字典 | 是否标准化 | 说明 |
| --- | --- | --- |
| 科室字典 | 是 | 编码唯一、类型受约束，管理页可维护 |
| 医生字典 | 是 | 编码唯一、归属科室、状态受约束 |
| 号别/费用字典 | 是 | 号别编码 + 挂号费/诊查费 |
| 药品字典 | 是 | 编码、通用名、规格、剂型、单位、单价、医保类别 |
| 医保类别 | 是 | 甲类/乙类/丙类/自费，导入与新增均校验 |
| ICD-10 诊断编码 | 否 | 当前诊断为自由文本；后续可接 ICD-10 字典表（实验十拓展项，本次不做） |
| 员工字典 | 部分 | `sys_user` 已含角色；未与医生字典做账号绑定 |

## 三、CSV 批量导入

支持列：`药品编码`、`通用名`、`商品名`、`规格`、`剂型`、`单位`、`单价`、`医保类别`、`库存数量`、`效期`、`生产厂家`。

规则：
1. 必需列：通用名、规格、单价；缺列直接拒绝并提示。
2. 编码识别顺序：`utf-8-sig → utf-8 → gbk → gb18030`，兼容 Excel 导出。
3. 逐行校验：必填、单价数字/非负、库存整数/非负、医保类别合法。
4. 去重：文件内按编码或“通用名+规格”；库内按编码或“通用名+规格”。
5. 错误行只记录不阻断，合法行继续入库；返回成功数、失败数、错误行号与原因。
6. 库存数量 >0 时同步创建库存批次。

演示文件：`static/drug_import_demo.csv`（100 合法 + 5 错误行，由 `scripts/gen_drug_csv.py` 生成）。

## 四、审计日志

记录时机：中间件拦截 POST/PUT/PATCH/DELETE，按 `app/services/audit.py` 的 `WRITE_RULES` 分类；登录/登录失败单独记录。

字段：用户 ID、用户名、动作、对象类型、对象 ID、详情、IP、时间。

查询：
- 页面：`/audit`（仅管理员），按用户、动作、日期过滤。
- API：`GET /api/audit?user_id=&action=&start=&end=&limit=`（仅管理员）。

已验证可查到：登录、挂号、退号、挂号收费、开方、处方收费、发药、药品导入、科室/医生维护、AI 分诊。

## 五、统计报表

`/report` 与 `GET /api/report/today` 输出：
- 今日挂号总量、退号量、退号率；
- 挂号收入（payment 已支付）；
- 处方收入（presc_payment 已支付）与处方数；
- 按科室：挂号量/退号/挂号收入/处方收入；
- 按医生：有效挂号量。

## 六、思考题：对接区域健康信息平台的数据模型改造（约 200 字）

需将患者主索引改为区域级唯一标识（如身份证+区域患者 ID 映射），补充就诊、诊断、处方、收费的标准编码（ICD-10、医保药品/诊疗目录、HL7/FHIR 资源），把当前自由文本诊断改为编码+名称双字段；增加数据同步表与幂等键，记录上传状态与失败重试；审计日志需保留数据交换轨迹；同时做字段级脱敏与最小必要上传，满足隐私与合规要求。
